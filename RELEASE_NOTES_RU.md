# Выпуск 0.7.0 — заметки (23.11.2026, не опубликован)

Версия 0.7.0 собрана локально (ветка f7-build). **Ничего не отправлено** на GitHub, PyPI и Zenodo; тегов нет. DOI не менялся.

## Что нового

Новая необязательная часть — `qoptct qualtran` (пакет `qoptct.foreign.qualtran`, extra `pip install "qoptct[qualtran]"`: Qualtran 0.7.0
и z3-solver). Без extra qoptct ставится и работает как раньше; новые тесты пропускаются. Доказатели `qoptct/verify/*` не менялись.

- **Строгий мост Qualtran → qoptct**: схема разбирается по вентилям (правила A1 и C1), `check_bloq` даёт PROVED / REFUTED (со свидетелем) / UNKNOWN.
- **Обращение Калиски**: исходная Qualtran, n от 16 до 256, три 256-битных простых (2^255−19, secp256k1, P-256); внутри проверка потока проводов (находка аудита AUD-D-01).
- **Умножение Монтгомери**: исправленная Qualtran (знак PR1997, таблицы без int64); n=256 окна 1 и 2, n=64 окно 4; внутри проверки покрытия и «свежести» проводов (AUD-C-01).
- **Сложение точек**: исправленная `ECAdd` при n=256; исходная `ECAdd` верна ровно вне групп G1–G3 (находка 05); `ECWindowAddR` с окнами 1, 2, 4.
- **Пары «прямой + обратный = тождество»** для Калиски и Монтгомери (зеркальная проверка по вентилям).
- **Реестр доказанного**: `qoptct qualtran results` (таблица; `--long` — допущения и команда воспроизведения каждой строки). Данные лежат в пакете.
- **Команда `qoptct qualtran`**: `check`, `prove kaliski|montgomery|ecadd|ecwindowaddr`, `pair kaliski|montgomery`, `results`. Код выхода 0 только при PROVED.
- Допущение прошлого раунда закрыто: Калиски и его пара при n=16, p=32749 теперь результаты; статус контрактов ECAdd при n=16 больше не содержит допущения.

Документация: `docs/QUALTRAN.md` (обзор, таблица, допущения; на английском), `docs/QUALTRAN_BRIDGE.md`, `_KALISKI.md`, `_MONTGOMERY.md`, `_ECADD.md`.

## Что доказано и при каких допущениях

Результат верен только для указанных n, p, w. Общая база: правила моста (A1, C1), лемма гаджетов AND/erase, доказатели qoptct, Z3.
Подробно по блокам — `docs/QUALTRAN.md`, раздел «Assumptions». Коротко:
- Калиски: шесть математических условий закрыты леммами Z3 для всех n, p, x; простота p (2^255−19 и secp256k1 — «известные простые» без сертификата); сборка программы из настоящих кусков — доверенная часть; при n=256 нужен файл канареек (он лежит в пакете и принимается только для ровно этой версии клиента).
- Монтгомери: итоговое «x·y·2^−n mod p, меньше p» следует из доказанных контрактов окон, инварианта T_i < y+p и телескопической суммы (два последних проверены кодом, не отдельным доказательством); инвариант для n>192 и w≥4 — интервальная арифметика.
- Сложение точек: ящики умножителя и обращения взяты с контрактами (данные `ecadd/contracts.py`, у каждого — результат реестра; где результата нет, вердикт — не PROVED, а PROVED_CONDITIONAL с кодом выхода 3; `--prove-boxes` доказывает недостающее тут же); три записи формул шагов совпадают только в точках; леммы о кривой проверены перебором при p ≤ 23.
- Пары: структурное (зеркальное) доказательство; сам прямой блок парой не проверяется.
- Не покрыто: x ≥ p, p = 2^n − 1, любые n и p вне таблицы реестра.
- Область p проверяется до счёта: для Калиски и сложения точек p должно быть простым (сертификат или известное простое), для умножителя и сложения точек 2p ≤ 2^n, p нечётное, p < 2^n − 1; иначе NOT_PROVED с причиной и код 1.
- «Оригинальная схема верна вне G1–G3» — доказывает пакет; то, что на G1–G3 схема грязная, показано в раунде 3 (находка 05), а не пакетом.
- Канарейки Калиски принимаются только от того же клиента: хеши файлов `kaliski/`, всего моста и `qoptct/verify` должны совпасть.

## Как проверено сборкой

Колесо `qoptct-0.7.0-py3-none-any.whl` собрано из клона ветки f7-build и установлено в два чистых venv (Python 3.12, macOS).
- Венв A (колесо + `[test]`, без Qualtran): старый набор `-m "not slow"` из установленного колеса — 1064 прошли, 39 пропущены (нужен Qualtran/Z3), 0 упали, включая `test_plugin`. Самый долгий тест — `test_v04_fixes::test_output_read_by_qiskit_and_proved[qft_4-balanced-extra0]`, около 585 с (не зависание, так же в общем venv); весь набор 22 мин.
- Венв B (колесо + `[test,z3,qualtran]`, Qualtran 0.7.0, Z3 5.4.1.0): быстрые `tests/foreign_qualtran` — все прошли; по одному медленному тесту n=256 на модуль: Калиски (2^255−19, 222 с), Монтгомери w=1 (223 с), ECAdd (1154 с), пары (61 с) — все PROVED.
- Из установленного колеса: `qoptct qualtran results` (33 результата, без Qualtran) и `qoptct qualtran prove montgomery --n 16 --w 1` — PROVED, код 0.
- Доказательства Калиски (канарейки n=256, 8 результатов, мутанты 18 из 18) и результаты n=256 Монтгомери/ECAdd пересчитаны финальным клиентом: статус и хеши программ те же, что до слияния.

## Важно перед публикацией

**Публикация 0.7 раскрывает найденные ошибки Qualtran (патчи и описания) — до публикации Максим решает, сообщать ли разработчикам.**
Раскрываются: знак в конце умножителя Монтгомери (PR1997, известный), переполнение int64 в таблицах, ошибка флагов `ECAdd` (находка 05; группы G1–G3, при окне 0 в `ECWindowAddR` срабатывает группа G3) — патчи лежат в `qoptct/foreign/qualtran/patches/` вместе с описаниями (`docs/QUALTRAN.md`). Разработчикам ничего не отправлялось.
Файлы Qualtran в `patches/src` — изменённые копии (Apache-2.0, Copyright Google LLC): это указано в `NOTICE`. Обратная схема `SynthesizeLRCircuit` (G2) и расчёты стоимости в 0.7 не входят.

# Выпуск qopt 0.2.0 — заметки (12.11.2026)

> Эти заметки относятся к выпуску 0.2.0. В 0.3.0 пакет переименован в `qoptct` (папка `qoptct/`, команда `qoptct`, `pip install qoptct`) — см. `CHANGELOG.md` и `PKG_NOTES_RU.md`.

Папка `release_qopt/` — чистая копия для будущей публикации: свой git (ветка main, только локальные коммиты),
ничего не опубликовано. Исходный проект `~/quantum-start` не менялся, кроме одной строки `release_qopt/` в `.gitignore`.

## Что внутри

| путь | что это |
|---|---|
| `qopt/` | пакет (команда `qopt`): `qopt_core.py` (бывший qopt.py), `verify_qasm.py`, `qiskit_qopt.py`, модули корня проекта, `portfolio/` (= cloud_v2/evolve + 13 программ портфеля), `proto2/`, `contrib/<агент>/` (c1, c2, c8, c10, c12, eng1, eng2, tg2, tg3 — только нужные файлы), `models/` (4 модели .pt, 15 МБ) |
| `bench_qc/` | 23 бенчмарка Feynman + `SOURCES.md` (происхождение, лицензия, SHA-256). **hwb6 исключён** (в файле запрет распространения), качается `scripts/fetch_benchmarks.sh` |
| `results/` | `best/<модель>/<схема>.qasm` (+ .json с происхождением), `pareto/<модель>/…`, `TABLE.md`, `table.csv`, `COMPARISON.md` (9 инструментов), `candidates.jsonl` (все 563 кандидата из проекта с вердиктом и SHA-256) |

| `tests/` | перенесённые тесты (плагин Qiskit, метрики) + новые `test_release.py` (проверятель, канарейки, защита кэшей, режим balanced, отсутствие абсолютных путей) |
| `docs/` | `METHOD.md` (методы), `FINDINGS.md` (найденные ошибки F1–F5) + `findings/*.py` (воспроизведение) |

| `_build/` (в .gitignore) | служебные скрипты сборки, ссылаются на исходный проект; в публикацию не идут |

Что изменено в коде при переносе (логика оптимизации не менялась):
- все пути абсолютные пути исходного проекта заменены на пути относительно файла; кэши и рабочие файлы агентов
  (tg2, tg3, c1) — в `$QOPT_CACHE` (по умолчанию `~/.cache/qopt`), а не внутрь пакета;
- кэш унитарных стартовых схем `contrib/eng1/ours/<имя>.json` и ручные конструкции `contrib/c1/best_clean`
  используются, только если SHA-256 входного файла совпадает с бенчмарком (раньше — по одному имени файла);
- VarTODD — только опция: путь к бинарнику через `QOPT_VARTODD_BIN`; без неё `--vartodd` ничего не делает;
- `verify_qasm` принимает схемы без строки `bit[...]` (унитарные); подкоманда `bench` заменена на `qopt version`
  и `scripts/reproduce.sh`; сообщения и справка CLI — на английском;
- пакет `qopt` реэкспортирует функции `qopt_core`, поэтому внутренние `import qopt` работают как раньше.

## Что проверено

Окружение: свежее `.venv-test` (Python 3.14.6 из /opt/homebrew, пакеты по `requirements.txt`, `pip install -e .`).

1. **pytest**: 25 из 25 тестов прошли (`tests/test_plugin.py`, `test_metrics.py`, `test_release.py`), ~25 с.
2. **scripts/verify_all.py**: все **200 из 200** строк `results/table.csv` прошли (T, CX и число кубитов в файле
   совпадают с таблицей; проверка: `verify_qasm` строго/clean до 22 кубитов, `verify_big` для больших схем
   с измерениями, PyZX/численно для больших унитарных). Первый прогон дал 196/200: 4 строки модели clean
   на 47/61 кубитах не имели проверяльщика — добавлена проверка строгим `verify_big` (строгая ⇒ clean), 4/4 прошли.
   Лог: `_build/verify_all.log`, `_build/verify_all_fix*.log`.
3. **Сбор результатов**: из 563 файлов-кандидатов исходного проекта проверены все, кто может попасть на Парето-фронт
   (265 прошли; 296 не проверялись, т.к. доминируются уже проверенными). 2 кандидата не прошли — это крупные
   унитарные схемы (qcla_com_7 из eng1/ours, qcla_mod_7 evo), для которых PyZX «не смог решить»; они не используются.
   Неверных схем среди кандидатов не найдено.
4. **qopt optimize в свежем окружении** на tof_3, tof_4, mod_red_21, qft_4 во всех режимах (cx, --net, --post, --meas,
   balanced, t, t --clean, balanced --clean, --tgad --vartodd) и сравнение с исходным проектом (`_build/venv_runs`
   против `_build/runs`): **9 из 10 прогонов дали тот же результат** (все числа отчёта совпадают). Отличается только
   `--tgad --vartodd`: промежуточная гаджетная схема 13/25 вместо 13/29 (в выпуске нет бинарника VarTODD, а доводка
   tg3 ограничена по времени); итоговый T тот же. Под аудит-хуком ни один прогон не обращался к файлам исходного
   проекта вне `release_qopt/` (зависимостей от старой папки не осталось).
5. **Сборка колеса** (`pip wheel .`): 126 файлов, модели .pt, данные c1/eng1 и точка входа `qopt` на месте.
6. Воспроизведение находок: F1 (hwb6 51 T — `ok=False`), F2 (Qrisp jones — случайные исходы), F4 (tket),
   F5 (Qualtran: CCZ = 7 T, CCX = 4 T) — перезапущены 12.11 и дают описанный результат. Одна запись разработки
   («Qualtran считает импортированный CCX как 7 T») при проверке оказалась неточной: 7 T даёт именно CCZ —
   исправлено в FINDINGS.

## Важные оговорки (их же стоит повторять в публикации)

- Три модели (унитарная / строгая с измерениями / чистые анциллы) нельзя сравнивать между собой; лучшая точка
  в моделях с измерениями выбрана по минимуму T (у qcla_com_7 и qft_4 это большие гаджетные схемы на 61 и 47
  кубитов с большим CX — их отдельно стоит пояснять; остальные точки — в `results/TABLE.md`).
- Проверка вероятностная (случайные входы и ветви измерений); строго доказаны только унитарные схемы ≤ 10 кубитов.
- Часть чисел — из долгих поисков при разработке (агенты c1, c2, c7, c8, c10, c12), а не из одного запуска `qopt`.
