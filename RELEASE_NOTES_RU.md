# Выпуск qopt 0.2.0 — заметки (12.11.2026)

Папка `release_qopt/` — чистая копия для будущей публикации: свой git (ветка main, только локальные коммиты),
ничего не опубликовано. Исходный проект `~/quantum-start` не менялся, кроме одной строки `release_qopt/` в `.gitignore`.

## Что внутри

| путь | что это |
|---|---|
| `qopt/` | пакет (команда `qopt`): `qopt_core.py` (бывший qopt.py), `verify_qasm.py`, `qiskit_qopt.py`, модули корня проекта, `portfolio/` (= cloud_v2/evolve + 13 программ портфеля), `proto2/`, `contrib/<агент>/` (c1, c2, c8, c10, c12, eng1, eng2, tg2, tg3 — только нужные файлы), `models/` (4 модели .pt, 15 МБ) |
| `bench_qc/` | 23 бенчмарка Feynman + `SOURCES.md` (происхождение, лицензия, SHA-256). **hwb6 исключён** (в файле запрет распространения), качается `scripts/fetch_benchmarks.sh` |
| `results/` | `best/<модель>/<схема>.qasm` (+ .json с происхождением), `pareto/<модель>/…`, `TABLE.md`, `table.csv`, `COMPARISON.md` (9 инструментов), `candidates.jsonl` (все 563 кандидата из проекта с вердиктом и SHA-256) |
| `scripts/` | `verify_all.py` (перепроверка всех схем таблицы), `reproduce.sh` (прогон на всех бенчмарках), `fetch_benchmarks.sh` |
| `tests/` | перенесённые тесты (плагин Qiskit, метрики) + новые `test_release.py` (проверятель, канарейки, защита кэшей, режим balanced, отсутствие абсолютных путей) |
| `docs/` | `METHOD.md` (методы), `FINDINGS.md` (найденные ошибки F1–F5) + `findings/*.py` (воспроизведение) |
| `paper/preprint.md` | черновик статьи (~4300 слов, ≈ 8–9 страниц) |
| `README.md`, `README_RU.md`, `LICENSE` (Apache-2.0), `NOTICE` (Copyright 2026 Maksym Shchehlov), `CITATION.cff`, `.zenodo.json` (без DOI), `CHANGELOG.md`, `pyproject.toml`, `requirements.txt`, `requirements-lock.txt` | |
| `_build/` (в .gitignore) | служебные скрипты сборки, ссылаются на исходный проект; в публикацию не идут |

Что изменено в коде при переносе (логика оптимизации не менялась):
- все пути `/Users/max/quantum-start/...` заменены на пути относительно файла; кэши и рабочие файлы агентов
  (tg2, tg3, c1) — в `$QOPT_CACHE` (по умолчанию `~/.cache/qopt`), а не внутрь пакета;
- кэш унитарных стартовых схем `contrib/eng1/ours/<имя>.json` и ручные конструкции `contrib/c1/best_clean`
  используются, только если SHA-256 входного файла совпадает с бенчмарком (раньше — по одному имени файла);
- VarTODD — только опция: путь к бинарнику через `QOPT_VARTODD_BIN`; без неё `--vartodd` ничего не делает;
- `verify_qasm` принимает схемы без строки `bit[...]` (унитарные); подкоманда `bench` заменена на `qopt version`
  и `scripts/reproduce.sh`; сообщения и справка CLI — на английском;
- пакет `qopt` реэкспортирует функции `qopt_core`, поэтому внутренние `import qopt` работают как раньше.

## Важные оговорки (их же стоит повторять в публикации)

- Три модели (унитарная / строгая с измерениями / чистые анциллы) нельзя сравнивать между собой; лучшая точка
  в моделях с измерениями выбрана по минимуму T (у qcla_com_7 и qft_4 это большие гаджетные схемы на 61 и 47
  кубитов с большим CX — их отдельно стоит пояснять; остальные точки — в `results/TABLE.md`).
- Проверка вероятностная (случайные входы и ветви измерений); строго доказаны только унитарные схемы ≤ 10 кубитов.
- Часть чисел — из долгих поисков при разработке (агенты c1, c2, c7, c8, c10, c12), а не из одного запуска `qopt`.
