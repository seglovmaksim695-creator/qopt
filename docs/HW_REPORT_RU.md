Ветка `f-route`, worktree `/Users/max/quantum-start/lab/work/f_route/repo`. Всё измерено на «фейковых» бэкендах
(сохранённые снимки калибровки реальных чипов IBM) и в шумовой симуляции Aer. На настоящем железе НИЧЕГО не запускалось.

## 1. Что сделано (метод простыми словами)

Задача: взять квантовую схему и превратить её в схему для реального чипа IBM (соединены не все кубиты, как соты;
родные вентили CZ/ECR, RZ, SX), так чтобы двухкубитных вентилей (самых шумных) было меньше, а ожидаемая точность выше.

Для каждой схемы строятся несколько кандидатов, выбирается лучший по ожидаемой точности, и ТОЛЬКО прошедший проверку:

1. `qiskit` — штатный транспайлер Qiskit, уровень 3, 10 разных seed (берётся лучший).
2. `qopt+qiskit` — сначала наша доказанная оптимизация логической схемы (CX/T у схем Клиффорд+T), потом Qiskit.
3. `hw` — наш маршрутизатор (в стиле SABRE, но с учётом того, что вентили коммутируют, с точной ценой SWAP: SWAP,
   соседний с вентилем на той же паре, сливается с ним и стоит +0..1 CZ вместо +3), затем объединение блоков и
   точный синтез двухкубитных блоков, и перенос схемы в лучшую по калибровке область чипа.
4. `qopt+hw` — то же на оптимизированной логической схеме.

Метрика «ожидаемая точность» = произведение (1 − ошибка) по всем вентилям × ошибки считывания × затухание T1/T2 кубитов
во время простоя (по калибровке). Это грубая модель первого порядка (без перекрёстных помех), она нужна для ранжирования.

Проверка корректности: схема на случайных произведённых состояниях сравнивается с исходной (с учётом перестановки кубитов),
вектор состояния до 26 использованных кубитов. Выше 26 — статус «не проверено» (честно помечено).

## 3. Шумовая симуляция Aer (подтверждение, что оценка ранжирует верно)

29 малых схем (до 10 кубитов), шумовая модель бэкенда с T1/T2 в простое, 4000 выстрелов, мера — точность Хеллингера с идеальным
распределением. Лучшая стратегия qoptct относительно Qiskit O3 (лучший из 10 seed): среднее геометрическое ×1.14, лучше на 26
из 29 схем; знак сравнения «оценка точности» совпал с симуляцией на 27 из 29. Это значит: оценка по калибровке годится
как ранжировщик кандидатов (при том же шумовом снимке; перекрёстных помех и дрейфа в симуляции нет).

## 4. Где выигрыш есть и почему

* **Арифметика на Toffoli (сумматоры, компараторы, mod5, Barenco)** — самый большой выигрыш (−40 %, точность ×1.85).
  Тут работают оба механизма: логическая оптимизация CX/T (доказанная) сокращает схему до маршрутизации, а маршрутизатор
  не плодит SWAP. Лучшие случаи: −69 % (qc_mod5_4), −59 % (add_vbe_4).
* **QFT, QAOA, Гамильтонианы** — много коммутирующих вентилей (контролируемые фазы, ZZ-слагаемые): маршрутизатор порядок
  выбирает под чип и сливает SWAP с вентилем (QFT на линии даёт 3 вентиля на пару вместо 6). Выигрыш 16–24 % по 2Q,
  глубина падает сильнее (−31…−44 %), так как вентили на разных парах идут параллельно.
* **Гровер** — выигрыш за счёт расположения и слияния; логическая оптимизация почти не помогает.

## 5. Где выигрыша нет (честно)

* Quantum volume (случайные двухкубитные унитарии без структуры): паритет с Qiskit (+1 % 2Q, точность ниже ×0.92) — портфель
  оставляет вариант Qiskit.
* Плотные решётки Гейзенберга 4×4: 2Q-вентилей меньше на 12 %, но оценка точности ниже (×0.88; наш вариант чуть длиннее
  по времени/хуже по ошибкам выбранных пар) — портфель оставляет Qiskit.
* Умножение в GF(2^m) (qc_gf2^5_mult): CX-минимальная логическая схема маршрутизируется ХУЖЕ исходной (структура CNOT менее
  локальна); итог +4 % 2Q, точность ×0.83 против лучшего Qiskit.
* BV_10: схема тривиальна (13–15 вентилей), у Qiskit точность выше при том же порядке.
* Портфель выбирает по оценке точности, а она — модель; на схемах с отрицательными знаками выше реальный риск ошибки выбора.

## 6. API и CLI

```
qoptct hw --backend fake_torino in.qasm -o out.qasm --report out.json [--seeds 5] [--seconds 20]
          [--objective fid|twoq|depth] [--strategies qiskit,qopt+qiskit,hw,qopt+hw] [--measure]
qoptct hw --list-backends
python -m qoptct.hw.bench run|sim|table   # воспроизведение бенчмарков (см. scripts/reproduce.sh)
```
```python
from qoptct.hw import compile_hw
r = compile_hw(qc, "fake_torino", seeds=range(5), seconds=20)
```
Код выхода: 0 — проверено; 2 — записано, но не проверено (>26 кубитов); 3 — ошибка входа. Документация: `docs/HW.md`, разделы в README и CHANGELOG.
Тесты: `tests/test_hw.py` — 24 теста, все проходят.

## 8. Ограничения

* Только унитарные схемы (без промежуточных измерений и классического управления).
* Оценка точности — модель по одному снимку калибровки; без перекрёстных помех, утечки, дрейфа. Подтверждено шумовой
  симуляцией Aer, но не железом. Сверку с реальными данными (qora_lab) делает другой исполнитель.
* Проверка эквивалентности только до 26 использованных кубитов (крупнейшая схема на 30 кубитов — «не проверено», в таблице помечено).
* Маршрутизатор на чистом Python, ~20 с на схему; Qiskit на порядок-два быстрее.
* Синтетические устройства (`line:N`, `heavyhex:D`) имеют случайную калибровку — только для тестов.
