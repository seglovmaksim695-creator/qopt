# Proofs about Qualtran blocks (`qoptct qualtran`, new in 0.7)

qoptct 0.7 proves that large reversible-arithmetic schemes of Google's **Qualtran** 0.7.0 are correct, gate by gate, with the
unchanged qoptct provers (BDD path sums, the compositional Walker, Z3 for glue).  Qualtran is an optional dependency:

```
pip install "qoptct[qualtran]"        # qualtran==0.7.0 and z3-solver; without the extra qoptct installs and works as before
```

Every verdict is positive-only: a result is `PROVED` or it is not; "skipped" and "unknown" are never proofs.  Without Z3 no
verdict of the clients below is `PROVED`; the Z3 version is written into every result.

## Parts

| part | module | what it proves | details |
|---|---|---|---|
| strict bridge | `qoptct.foreign.qualtran.bridge`, `check_bloq` | any small bloq against its `call_classically`, gate by gate | [QUALTRAN_BRIDGE.md](QUALTRAN_BRIDGE.md) |
| Kaliski inversion | `...qualtran.kaliski` | `KaliskiModInverse(n, p)` (original Qualtran), wire-flow check included | [QUALTRAN_KALISKI.md](QUALTRAN_KALISKI.md) |
| Montgomery multiplication | `...qualtran.montgomery` | `DirtyOutOfPlaceMontgomeryModMul(n, w, p)` (patched Qualtran), coverage and freshness checks of the window pieces included | [QUALTRAN_MONTGOMERY.md](QUALTRAN_MONTGOMERY.md) |
| point addition | `...qualtran.ecadd` | `ECAdd(n, p)` (fixed scheme) and `ECWindowAddR(n, p, window)`, contracts of the two boxes as data | [QUALTRAN_ECADD.md](QUALTRAN_ECADD.md) |
| pairs | `...qualtran.pairs` | block followed by its `uncompute=True` twin is the identity (Kaliski, Montgomery) | [QUALTRAN_ECADD.md](QUALTRAN_ECADD.md) |
| registry | `...qualtran.registry`, `qoptct qualtran results` | the table of the proved results below, with variant, hashes, assumptions, command | this file |

## Command line

```
qoptct qualtran check "qualtran.bloqs.arithmetic.addition.Add(QUInt(3))"
qoptct qualtran prove kaliski|montgomery|ecadd|ecwindowaddr --n N [--p P] [--w W | --window W] [--original] [--prove-boxes] [--out FILE]
qoptct qualtran pair kaliski|montgomery --n N [--p P] [--w W] [--out FILE]
qoptct qualtran results [--name NAME] [--n N] [--long] [--json]
```

The exit code is 0 only for `PROVED` (and `results` after printing).  1: not proved, refuted, a modulus outside the domain of the
proof (see `QUALTRAN_ECADD.md`), or (for `ecadd --original`) the different statement `PROVED_OUTSIDE_G1_G3`; 2: `check` returned
`UNKNOWN`; 3: `PROVED_CONDITIONAL` (`ecadd`, `ecwindowaddr`: proved, but a box contract is only assumed for this n, p; `--prove-boxes`
proves the missing ones in the same run); 4: usage error or Qualtran missing (this was 3 in the first build of 0.7).
`--p` defaults: 32749 at n = 16, 2^255 - 19 at n = 256 (Montgomery: the largest prime <= 2^(n-1)); other n need `--p`.
The modules keep their own `python -m qoptct.foreign.qualtran.<module>` command lines (flags in each document).
Heavy sizes (n = 256) take minutes up to an hour and about 3 GB; run them one at a time.  Work files and the patched copies
of Qualtran go to `$QOPT_CACHE` (default `~/.cache/qopt`); the installed Qualtran is never modified.

## What is proved (the registry)

`qoptct qualtran results` prints the table; `--long` adds claim, assumptions and command of each row.  The data are in
`qoptct/foreign/qualtran/data/registry.json` (inside the installed package), generated by
`scripts/build_qualtran_registry.py` from the result files `results/qualtran/*.json` (the registry stores the SHA-256 of
each file; `tests/foreign_qualtran/test_registry.py` checks both).

| name | Qualtran | instances in the registry | statement |
|---|---|---|---|
| `kaliski_inverse` | original 0.7.0 | n = 16 (p = 32749); n = 64 (2 primes); n = 128 (2 primes); n = 256 (2^255 - 19, secp256k1, P-256) | output `x^-1 * 2^(2n) mod p` (0 for x = 0), junk register as stated, all other wires clean, every `0 <= x < p` |
| `montgomery_mul` | patched, kind `c` | n = 16 w = 1; n = 256 w = 1 and 2 (p = 2^255 - 19); n = 64 w = 4 | `target = x*y*2^-n mod p`, `< p`, garbage registers as stated, all other wires clean, no phase; every `y < p`, every n-bit `x` |
| `pair_kaliski` | original | n = 16 (65521, 32749); n = 32, 64, 128; n = 256 (2^255 - 19, secp256k1, P-256) | forward + `uncompute=True` is the identity on all wires (exact phase, all outcomes) |
| `pair_montgomery` | patched, kind `c` | n = 16, 64, 128, 256 with w = 1 | the same |
| `ecadd` | patched, kind `e` (`original` for the second row) | n = 16, 256 (fixed); n = 16 (original) | fixed: the point addition in Montgomery form, all special cases; original: `PROVED_OUTSIDE_G1_G3` |
| `ecwindowaddr` | patched, kind `e4` | n = 16 and 256, window 1, 2, 4 | `(c, Q) -> (c, Q + c*R)` given the `ECAdd` contract |

A result holds for the stated `n`, `p`, `w` only.  Nothing is claimed for other n or for inputs outside the stated domains
(for example `x >= p`, `p = 2^n - 1`).

### Qualtran variants and patches

Three results are about Qualtran as installed (Kaliski, its pair, the original `ECAdd`).  The multiplier, point addition and
their pairs are proved for **patched copies** (`qoptct.foreign.qualtran.patches`; the files and their SHA-256 are in
`patches/manifest.json`, the differences in `patches/diff/`).  The patches are applied to a copy in `$QOPT_CACHE`; every
proof client checks which variant it really imported and answers `NOT_PROVED` for any other.

| kind | content | used for |
|---|---|---|
| `c` | final reduction subtracts p instead of adding it (Qualtran PR 1997); QROM/Montgomery tables as exact Python integers (no int64) | `montgomery_mul`, `pair_montgomery` |
| `e` | flag fix of `ECAdd` (E05) + the same + exact table | `ecadd` |
| `e4` | `e` + the QROM files of `c` | `ecwindowaddr` |

### Findings about Qualtran 0.7.0 that the proofs depend on

Stated as checked facts, with the reproduction in the code and the tests.

1. **`DirtyOutOfPlaceMontgomeryModMul`, final reduction.**  The original circuit adds p to the target when `T_N >= p`.  The
   fixed contract `target = T_N - p*[T_N >= p]` is violated on the inputs with `T_N >= p` (about a quarter of all inputs;
   `prove montgomery --n 16 --w 1 --original` is `NOT_PROVED` with a witness).  This is the sign fixed by Qualtran PR 1997.
2. **Tables of the Montgomery window.**  The data tables are computed in `int64`, which overflows above 63 bits; the patch uses
   exact integers.
3. **`ECAdd` flags (finding 05).**  On three groups of inputs (G1-G3; predicates in `ecadd/glue.py`, `groups`) the original
   scheme leaves a flag wire non-zero.  The original scheme is proved correct outside these groups
   (`ecadd --original`: `PROVED_OUTSIDE_G1_G3`; that the scheme is dirty on the groups was shown in round 3, finding 05, and is not
   re-checked by the package).  The patch costs about 5n Toffoli gates.  In `ECWindowAddR` the table row for
   window value 0 is (0, 0, 0), i.e. the point at infinity, which belongs to group G3.

Neither the findings nor the patches were sent to the developers of Qualtran.

## Assumptions

The common base of every result: the rules of the bridge (A1 controlled-And, C1 `QROAMCleanAdjoint` with the assumptions A1-A4
written in `bridge/qroam_clean_adjoint.py`), the gadget lemma for AND/erase of qoptct, the qoptct provers (`qoptct.verify`,
unchanged), and Z3 (5.3.3 in the registry).  Per block (the registry lists them per row):

* **Kaliski**: the six mathematical conditions M-carry, M-dbl, M-a, M-s, M-end, M-end-vf are closed by Z3 lemmas for all n, p, x
  (243 implications and 25 controls that must fail); p prime (2^255 - 19 and secp256k1 are accepted as known primes, no
  certificate); the composition of the program from the real pieces is trusted (checked against the full expansion at small n
  and by an independent simulation); at n = 256 the verdict needs the canary evidence (see below).
* **Montgomery**: the claim `x*y*2^-n mod p` follows from the proved window contracts, the invariant `T_i < y + p` and the
  telescoping sum; the last two are checked by code, not by a separate proof.  The invariant of the generic window is analytic
  (interval arithmetic) for n > 192 and w >= 4.  For w >= 4 the composition of the sub-nodes is by wire positions, interval
  arithmetic and integer runs, not by BDD.
* **Point addition**: the multiplier (window 1) and the Kaliski inverse are boxes with contracts, listed as data in
  `ecadd/contracts.py` together with the registry result for each (n, p).  For an instance without a result the contract is
  `ASSUMED_FOR_THIS_INSTANCE` and the verdict is `PROVED_CONDITIONAL` (exit code 3), not `PROVED`, unless `--prove-boxes` proves the
  missing contracts in the same run.  With 0.7 the n = 16, p = 32749 instance is covered for both boxes and their pairs.  The three
  records of the step formulas (BDD, Z3, integer) agree on sample points only (n = 16: 3000 per step, n = 256: 600 per
  step); the curve lemmas used by the glue were checked by brute force for p <= 23 and are not proved for 2^255 - 19.
  `ECWindowAddR` uses the contract of `ECAdd` for the same n, p, rule C1 and `QROAMClean` with K = 1, window sizes 1, 2, 4,
  the curve `y^2 = x^3 + 2x + 3` and one fixed point R.
* **Pairs**: a structural argument at gate level (the second half is the mirror of the first up to a renaming of wires); the
  forward block itself is not verified by the pair check.

### Canary evidence for Kaliski at n = 256

The verdict at n = 256 requires evidence that the client rejects damaged copies of the real circuit (canaries; about 45 minutes
to produce).  The evidence file is shipped in the package (`qoptct/foreign/qualtran/data/kaliski_canaries_n256.json`) and used
when no file is given and `$QOPT_CACHE/kaliski/canaries_n256.json` does not exist.  It is accepted only if it was made by exactly
the installed client: the verdict compares the SHA-256 of the seven client source files (`kaliski/`), of the whole bridge
(`bridge/*.py`) and of the qoptct provers (`qoptct/verify`) stored in the file with the installed ones, so a changed client, bridge or prover gives `NOT PROVED (canaries)` until the canaries are regenerated
(`python -m qoptct.foreign.qualtran.kaliski canaries --n 256 --p '2**255-19' --out FILE`).  The Z3 lemmas are not shipped: they
are recomputed once (about 150 s) and cached.

### Known limitations (from the independent audit of 0.7)

* `qoptct qualtran check` builds the bloq by evaluating the given expression as Python (Qualtran names, a few builtins).
  This is not a sandbox: do not pass text from an untrusted source.  Numbers (`--n`, `--p`, ...) are read without `eval`.
* Kaliski canaries: the packaged evidence contains the run of 27 candidates (13 targeted + 12 random + the rerun of T8b); the wide
  search for a witness beyond the standard sample inputs (the `extra` field, supported by the verdict) was done in round 3 and is not
  repeated by the package.  The counting rule is the same as in round 3.
* `prove montgomery --original`: the installed Qualtran is only recorded (`installed original`), its being the unmodified 0.7.0 is
  not checked by hash.  There is no PROVED result for the original scheme.
* Montgomery: the work-cache key uses the first 16 hex digits of p; another p with the same start gets `NOT_PROVED` ("cache does not
  belong to this request") and the command has no `--fresh` (use a new `$QOPT_CACHE`).  Window 0 for w <= 2 is proved whole; when that
  returns UNKNOWN (budget), it is proved by sub-nodes with the analytic glue (a path tested by `test_f7_montgomery_fallback.py`;
  structural checks alone do not see a damage in window 0, the proof of the sub-node does).
* Kaliski does not compare the installed Qualtran version with 0.7.0 (it is recorded in the result); Montgomery and point addition do.
* A damaged input that the bridge cannot lower (a pair whose half is not a mirror, a wire layout the bridge refuses) is reported as
  status `ERROR` by the API (not PROVED, exit code non-zero), not as a verdict with a reason.
* The curve lemmas of the glue were checked by brute force for small p only; the three records of the step formulas agree on sample
  points (see Assumptions).

## Reproduce

```
pytest tests/foreign_qualtran                 # fast tests (about 3 minutes), skipped without Qualtran
pytest tests/foreign_qualtran -m slow         # n = 256 reruns, minutes each; run them one at a time
qoptct qualtran results --long                # the command of every result is in its `reproduce` line
qoptct qualtran prove montgomery --n 16 --w 1
qoptct qualtran prove kaliski --n 16 --p 32749
qoptct qualtran pair kaliski --n 16 --p 32749
qoptct qualtran prove ecadd --n 16
```

The result files of the repository are written by the same commands with `--out results/qualtran/<name>.json`; the file name
of each registry row is in its `source` field.  After a new run: `python scripts/build_qualtran_registry.py`.

## Scope

0.7 contains the proofs listed above and the strict bridge.  Other analyses of the same research round (cost counts, GF(2^m)
blocks, the reverse-circuit finding `SynthesizeLRCircuit`) are not part of the package.
