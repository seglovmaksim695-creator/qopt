# qopt — проверяемый оптимизатор схем Clifford+T

[![PyPI](https://img.shields.io/pypi/v/qoptct.svg)](https://pypi.org/project/qoptct/)
[![tests](https://github.com/seglovmaksim695-creator/qopt/actions/workflows/tests.yml/badge.svg)](https://github.com/seglovmaksim695-creator/qopt/actions/workflows/tests.yml)
[![DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.24182059.svg)](https://doi.org/10.5281/zenodo.24182059)

> **Имя пакета.** Проект называется *qopt*, но имя `qopt` на PyPI занято другим, не связанным проектом. Поэтому
> начиная с версии 0.3.0 пакет устанавливается и импортируется как **`qoptct`**: `pip install qoptct`,
> `import qoptct`, команда `qoptct`.

`qopt` уменьшает **число T** и **число CNOT (CX)** в схемах Clifford+T, заданных как сети Тоффоли (формат Feynman
`.qc`). Есть унитарный режим и режимы с измерениями. Программа **никогда не выдаёт непроверенную схему**: унитарный
результат доказывается равным входу (иначе возвращается вход), а каждая схема с измерениями перед записью
доказывается точным прувером `qoptct.verify` или, если доказательство не укладывается во время, перепроверяется
независимыми симуляторами на многих случайных входах и исходах измерений (в отчёте JSON указано, как именно).

Репозиторий: <https://github.com/seglovmaksim695-creator/qopt> · Версия 0.6.0 (не опубликована) · Лицензия Apache-2.0 (файлы бенчмарков — см. `bench_qc/SOURCES.md`) · Автор: Maksym Shchehlov

Основная документация — на английском (`README.md`, `docs/METHOD.md`, `docs/FINDINGS.md`). Здесь — краткое изложение.

## Установка

```bash
pip install qoptct              # Python 3.11+, macOS или Linux; команда `qoptct` и плагин Qiskit
pip install "qoptct[net]"       # по желанию: + PyTorch для нейросетевого режима --net
pip install "qoptct[qcec]"      # по желанию: + MQT QCEC как дополнительная проверка унитарных схем
```

Зависимости: numpy, qiskit ≥ 2.0, pyzx. PyTorch нужен только для `--net`; без него остальные режимы работают,
а `--net` останавливается с сообщением, что именно установить.

Из репозитория (тесты, бенчмарки, скрипты):

```bash
git clone https://github.com/seglovmaksim695-creator/qopt.git && cd qopt
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt                      # точные версии, на которых получены результаты (вкл. torch)
pip install -e ".[test]"
pytest -q tests                                      # несколько минут
```

## Использование

```bash
qoptct optimize bench_qc/tof_3.qc -o tof_3_opt.qc                     # унитарно, минимум CX (режим по умолчанию)
qoptct optimize bench_qc/tof_3.qc -o tof_3.qasm --mode balanced       # меньше T, CX не больше 1,5 × унитарного
qoptct optimize bench_qc/mod_red_21.qc -o m.qasm --mode t --clean     # минимум T, модель «чистые анциллы»
qoptct optimize X.qc -o x.qasm --mode t --prove                       # + точное доказательство записанного результата
qoptct prove x.qasm X.qc                                              # точное доказательство любого выхода против входа
```

Опции: `--net` (нейросетевой блочный ресинтез, нужен `pip install "qoptct[net]"`), `--post` (пост-проход CX),
`--meas` (старый режим Гидни), `--tgad`/`--vartodd` (гаджеты H + TODD; внешний VarTODD — через переменную
`QOPT_VARTODD_BIN`), `--report r.json`. Кэши пишутся в `$QOPT_CACHE` (по умолчанию `~/.cache/qopt`).
Унитарный результат пишется в `.qc`, а если имя файла `-o` оканчивается на `.qasm` — в OpenQASM 3; результаты с
измерениями — всегда OpenQASM 3, читаемый `qiskit.qasm3.loads` (условия — один измеренный бит или его отрицание,
возможно вложенные). Если стадия дала условие с `^` или `&&`, результат переписывается (условие вычисляется в
свободный измеренный кубит и измеряется ещё раз — те же T и CX, на одно измерение больше; или поправка повторяется
по слагаемым) и заново доказывается; подсчёты до и после — в `final.qiskit_rewrite`. Промежуточные файлы стадий
лежат во временном каталоге (удаляется в конце, `--keep-temp` — оставить), `-o` записывается атомарно. Коды выхода `qoptct optimize`: 0 — результат записан; 3 — ошибка вызова или входа
(нет файла, файл не читается, битая схема, неизвестный вентиль, необъявленный провод, нет каталога для `-o`) — одна
строка `error: ...` в stderr.
Из Python: `import qoptct; names, ref, best, how = qoptct.optimize("X.qc")`.

### Дополнительные модули и точные доказательства (новое в 0.4)

| модуль | что делает |
|---|---|
| `qoptct.contrib.arith` | распознаёт классическую арифметику (сумматоры, компараторы, сложение по модулю 2^n−1, hidden weighted bit) по таблице истинности и строит её заново на логических И |
| `qoptct.contrib.bandc` | компилятор логических И для больших классических схем (сотни–1600 проводов) с точным отслеживанием значений проводов |
| `qoptct.contrib.gf2m` | умножители GF(2^m) по билинейным разложениям малого ранга (таблицы входят в пакет) |
| `qoptct.contrib.cxpass` | пост-проход CX: ресинтез блоков CX/фаз, слияние поправок (в т.ч. с условием XOR) |
| `qoptct.verify` | точный прувер и быстрые проверки |

Каждый модуль работает в отдельном процессе с жёстким лимитом времени; ошибка или таймаут модуля только пропускает
его, а **каждую схему модуля ядро проверяет заново**. Опции: `--no-arith`, `--no-bandc`, `--no-gf2m`, `--no-cxpass`,
`--no-contrib` (поведение 0.3), `--budget S` (общее время модулей, по умолчанию 1500 с), `--contrib-sec`,
`--source-sec ИМЯ=С`, `--require-proof` (выше 22 кубитов — только доказанные результаты), `--prove`;
`--and-sec S` — время перебора вариантов компилятора логических И в режимах balanced/t (по умолчанию 1800 с, 0 — без
ограничения); `--time-limit S` — общее время запуска (по умолчанию 3600 с, 0 — без ограничения): поиски на этом
останавливаются все поиски (унитарный портфель и его доказательства, модули, стадии с измерениями) и записывается
лучший уже проверенный результат (в худшем случае — сам вход); после этого возможна только финальная проверка
записанного результата с измерениями (или `--prove`): обычно меньше минуты, не более ~15 мин.

Приём кандидата: до 22 кубитов — симулятор (30 входов), затем точное доказательство; если оно не успело — усиленная
выборочная проверка (64–256 случайных входов со случайными исходами измерений). Больше 22 кубитов — точное
доказательство; при UNKNOWN — выборочные проверки `qoptct.verify` (это не доказательство, отчёт так и пишет).
Опровергнутый (REFUTED) результат никогда не записывается.

`qoptct prove СХЕМА ВХОД.qc [--clean] [--budget С]` — точное доказательство (все базисные входы и все комбинации
исходов измерений); печатает JSON, код выхода 0 PROVED, 1 REFUTED, 2 UNKNOWN, 3 — ошибка вызова или входа (ошибка
входа никогда не выдаётся как REFUTED; так же у `python -m qoptct.verify`). Прувер работает в отдельном процессе,
поэтому его можно вызывать из скриптов без `if __name__ == "__main__":` и из плагина Qiskit
(`QoptPass(cxpass=True)` добавляет пост-проход CX с повторным доказательством).

`qoptct kprove СХЕМА.qasm ЭТАЛОН.qc [--clean] [--budget С] [--engine auto|bdd|anf|sample|exact2] [--max-mb МБ]
[--json]` (новое в 0.5) — точный прувер для больших схем
с *классическим* эталоном (арифметика, табличные выборки, S-box): тот же путь-интеграл с символьными исходами
измерений, но функции проводов — BDD, поэтому сумматоры на тысячи бит доказываются за секунды. Коды выхода как у
`prove` (2 — также SAMPLED: выборочная проверка, не доказательство). Движок BDD останавливается с UNKNOWN, если
память, занятая за время вызова (прирост резидентной памяти), превышает `--max-mb` / `kprove(max_mb=...)` /
`$KPROVE_MAX_MB` (по умолчанию 900 МБ); умножения и редукции по общим простым обычно его превышают. В режиме по
умолчанию `--engine auto` после этого работают движок ANF (в отдельном процессе, этим лимитом не ограничен) и
выборочная проверка, поэтому итог тогда обычно SAMPLED (код 2). `--engine bdd` запускает только BDD и держит весь
вызов в пределах лимита. Для схем, где все провода имеют
степень ≤ 2 над GF(2) (умножители GF(2^m)), движок `exact2` решает точно при любом размере по входам веса ≤ 2;
`auto` пробует его первым, если эталон билинейный.

`qoptct aprove СХЕМА.qasm СПЕЦИФИКАЦИЯ.json [--budget С] [--json]` (новое в 0.6; тот же движок —
`qoptct kprove СХЕМА.qasm СПЕЦИФИКАЦИЯ.json --engine algebra`) — словный (word-level) алгебраический прувер для
целочисленной арифметики, которую BDD не берёт: умножители, квадраты, редукции по специальным простым и их склейки
на логических И со стиранием измерением. Спецификация — JSON со входными словами, выходными словами и целочисленными
утверждениями, например `{"inputs": {"x": {"range": [0, 256]}, "y": {"range": [256, 512]}}, "outputs": {"out":
{"range": [512, 1024]}}, "claims": ["out == x*y"], "garbage": []}`. PROVED означает: для каждого базисного входа и
каждой комбинации исходов измерений схема вычисляет классическую функцию, для которой утверждения верны, входные
провода не изменены, остальные провода возвращены в |0> (мусорные — любая классическая функция), и ни у одной ветви
нет фазы, зависящей от входа. `multiply` / `square` при n = 256 с уровнями Карацубы 0..3 — 4–9 с и не больше 0,8 ГБ;
fold-редукции — меньше секунды; умножение по модулю Curve25519 / secp256k1 / P-256 целиком — 9–18 с
(`python scripts/algebra_proofs.py proofs`). Это не общий проверяльщик эквивалентности: схемы, не состоящие из
цепочек переносов, получают UNKNOWN (код 2), а с вентилями вне строгого языка — ошибку входа (код 3); несколько
правильных схем Карацубы на очень узких или нечётных листьях тоже остаются UNKNOWN.
При n = 256 доказано: умножение и возведение в квадрат (уровни Карацубы 0..3), fold-редукции для Curve25519, secp256k1,
P-256, P-384, P-521 и умножение по модулю целиком для трёх из них. Остаётся UNKNOWN: квадрат с Карацубой уровня >= 2 на
нечётных или очень узких ширинах, `square(256, 3, legacy=True)` и всё, что не является арифметикой на цепочках
переносов (управляемые обмены, произвольная булева логика; например обращение Калиски — см. `qoptct compose`).

`qoptct compose` (новое в 0.6; `python -m qoptct.verify.compose`) доказывает обращение Калиски `kaliski_inverse` при
n = 256 (secp256k1, P-256, случайное 256-битное простое; приведение generic и special; прямая и clean-схема; Curve25519,
P-384 и P-521 — в режиме clean со special-приведением) на настоящем тексте OpenQASM (250–520 МБ), 40–250 с и около
0,5 ГБ на схему: PROVED для каждого x из [1, p) и каждой комбинации исходов измерений. У доказательства есть слои, и
они не одинаково сильны: 2 061–2 302 сегментов схемы проверяются машиной на соответствие их контрактам (BDD), леммы о
гаджетах — точная арифметика; леммы о целочисленном алгоритме (границы, чётность, инвариант u·s + v·r = p) машина Z3
проверяет для всех n и p (`pip install "qoptct[z3]"`, нужен бинарник `z3`); склейка сегментов и связь записи для Z3 с
контрактами — рассуждение, записанное в `qoptct/verify/compose/PROOF.md`, а не машинная проверка. Покрыта только
конструкция по умолчанию (`legacy=False`).

## Плагин Qiskit

После `pip install qoptct` в транспиляторе Qiskit появляются два плагина стадий с именем `qoptct`:
`optimization_method="qoptct"` (обычная оптимизация Qiskit выбранного уровня, затем `QoptPass` на частях схемы в
базисе Clifford+T) и `init_method="qoptct"` (`QoptPass` на схеме, пока Тоффоли ещё не разложены, — здесь
основная экономия).

```python
from qiskit import QuantumCircuit, transpile
from qiskit.quantum_info import Operator

qc = QuantumCircuit(5)
qc.ccx(0, 1, 4); qc.ccx(2, 4, 3); qc.ccx(0, 1, 4)
basis = ["h", "x", "z", "s", "sdg", "t", "tdg", "cx"]                 # Clifford+T
ours = transpile(qc, basis_gates=basis, optimization_level=3,
                 init_method="qoptct", optimization_method="qoptct")
assert Operator(ours).equiv(Operator(qc))                              # тот же оператор с точностью до глобальной фазы
```

Пример (CX/T, Qiskit 2.6.2, базис Clifford+T): tof_3 — Qiskit 18/19, с плагином 12/15; mod5_4 — 28/22 → 11/8.
Часть схемы заменяется, только если новая версия **доказанно** равна старой, строго дешевле (CX, затем T) и
использует только разрешённые базисом / картой связей / target вентили и пары кубитов; всё остальное (измерения,
повороты, другие вентили) не трогается. Правило «строго дешевле» действует для каждой заменённой части; следующие
стадии `transpile` (например, синтез поворотов) могут изменить итог, поэтому на схемах с поворотами сравнивайте
итоговые числа с плагином и без него. Глобальная фаза сохраняется точно для частей до 10 кубитов. Проход можно
использовать и напрямую:
`from qoptct.qiskit_qopt import QoptPass`.

## Компиляция под шумное железо: `qoptct hw` (новое в 0.6, экспериментально)

`qoptct hw` компилирует унитарную схему под устройство типа IBM (решётка heavy-hex, родные вентили CZ или ECR + RZ, SX, X)
и уменьшает то, что важно на шумном железе: число двухкубитных вентилей после маршрутизации, глубину и ожидаемую
точность, посчитанную по калибровке бэкенда.

```
pip install "qoptct[hw]"
qoptct hw --backend fake_torino in.qasm -o out.qasm --report out.json
```

Это портфель кандидатов: Qiskit `optimization_level=3` (по одному запуску на seed — всегда в наборе, поэтому по
используемой метрике результат не хуже Qiskit), логическая оптимизация CX/T qoptct + Qiskit и собственный
маршрутизатор qoptct (учёт коммутации вентилей, точная цена SWAP по KAK-разложению при слиянии с соседним вентилем,
«плавающие» блоки, зеркальное правило, раскладка вдоль линии, перенос в лучшую по калибровке область). Каждая
выдаваемая схема проверяется на эквивалентность исходной с учётом перестановки кубитов (до 26 использованных
кубитов). На настоящее железо ничего не отправляется; `scripts/hw_real_run.py` только готовит один короткий прогон
и не отправит его без `--submit` и `QOPT_ALLOW_REAL=1`.

Где собственный вариант хуже, в портфеле остаётся вариант Qiskit, поэтому по этой метрике результат не хуже Qiskit
уровня 3. Все цифры точности — оценка по модели чипа и снимку калибровки (fake-бэкенды), на реальном железе не измерено. Сверка с реальными запусками: на 8 реальных заданиях IBM (ibm_fez, ibm_marrakesh; 286 строк результатов, один снимок калибровки на чип) оценка по калибровке занижала ошибку примерно в 1,6 раза (1,6–1,7 у сравниваемых моделей). Для предварительного выбора между вариантами она полезна: правильно упорядочила 93,7 % различимых пар (Fez — 100 %, Marrakesh — 76,4 %, там всего 6 задач). Абсолютным числам точности доверять нельзя. Поправочный множитель подобран, но не прошёл критерий точности и в код не вшит.

Метод, таблицы сравнения с Qiskit и tket, шумовая симуляция и ограничения — в [`docs/HW.md`](docs/HW.md).

## Стирание измерением на железе: `qoptct dyn` (новое в 0.6, экспериментально)

На чипах IBM по умолчанию используется обычное (статическое) снятие логического И (обратный гаджет, 3 CX); стирание
измерением с классической поправкой не применяется, пока проход не найдёт, что оно выигрывает. `qoptct.dyn` собирает
варианты арифметического блока (статический, гибрид, с измерением) под калибровку бэкенда и оставляет вариант с лучшей
ожидаемой точностью; гибрид (одиночные И снимаются обратным ходом, многочленные стираются измерением) выбирается для
блоков «выборка + сложение», когда он лучше. По нашим моделям динамика на сегодняшних чипах не выгодна (измерение с
передачей поправки простаивает всеми живыми кубитами около 2,8 мкс). `qoptct dyn choose adder 4 --backend FakeBoston`;
с `--route СЕК` статический вариант собирается через `qoptct.hw`. Установка: `pip install "qoptct[dyn]"`. Цифры — по
модели чипа и снимку калибровки, на реальном железе не измерено.

## Модели стоимости — обязательно перед сравнением чисел

| модель | что разрешено на выходе | входные провода | анциллы | чем проверяется |
|---|---|---|---|---|
| **унитарная** | только вентили Clifford+T на тех же проводах | любое состояние | нет | полная матрица / PyZX / численно |
| **строгая** (с измерениями) | + свежие анциллы в \|0>, измерения посреди схемы, клиффордовы вентили по результату измерения | **все** провода `.qc` — данные в любом состоянии, включая провода, задуманные в бенчмарке как анциллы | свежие должны вернуться в базисное состояние, не запутанные с данными | `verify_qasm` (строго), `verify_big` |
| **чистые анциллы** | как строгая | данные — только провода из строки `.i`; **остальные провода `.qc` стартуют в \|0> и должны вернуться в \|0>** (так задуманы `tof_n`, `mod_red_21` и др.) | как строгая | `verify_qasm(clean=True)` |

Строгая модель сильнее: схема, верная в строгой модели, верна и в модели чистых анцилл, но не наоборот. В обеих
моделях с измерениями логическое И стоит 4 T, а его снятие — 0 T (Гидни, 2018), поэтому T там намного ниже
унитарного. Сравнивать такие T с унитарными рекордами нельзя; рекорды с гаджетами H (TODD, AlphaTensor-Quantum) —
ещё одна, третья модель.

## Криптографические блоки (новое в 0.5)

В `results/crypto/` — схемы блоков квантовых атак на AES и ЭК-криптографию с эталонами (`.qc`) и записями `.json`

### Генераторы: `qoptct.crypto` (новое в 0.5)

Чистые функции (одни и те же аргументы — одна и та же схема), которые строят арифметику этих атак в модели
логических И; вывод OpenQASM 3, битслайс-проверка, для малых размеров — точное доказательство в тестах. Счёт — в
логических И (= Тоффоли, по 4 T).

| функция | что | счёт | сравнение |
|---|---|---|---|
| `kaliski_inverse(p, n=None, reduction='generic'\|'special', clean=False, legacy=False)` | обращение Калиски, результат −x⁻¹·2^{2n} mod p | 12n²−8n−3 И в прямой схеме (generic; `legacy=True`: 12n²+n), 11n−2 кубитов (generic); P-256 special 664 966 И / 5 513 кубитов, secp256k1 657 503 / 3 107 | Litinski 2023 (arXiv:2306.08585): 26n²+2n в той же модели. fold.reduce_special(fold.P25519).n_and                 # 1304

```python
lookup.narrow_lookup(table, 6, 32).n_and               # 40 для большинства случайных таблиц (иногда 41)
gf2m_mult_count(163, default_modulus(163))['AND']      # 908
c = square(8); qasm, ref = c.to_qasm(), c.reference_qc()   # схема и независимый эталон для `qoptct kprove`
```

### Физическая стоимость: `qoptct estimate` (новое в 0.5)

`qoptct.estimate` переводит логические числа (Тоффоли/И, логические кубиты, по желанию глубина реакций) в
физические кубиты, время и вероятность сбоя прогона на поверхностном коде. Это **формульные модели, откалиброванные
на статьях** — `ge2019` (Gidney–Ekerå 2019, arXiv:1905.09749), `gidney2025` (Gidney 2025, arXiv:2505.15917),
`litinski2023` (Litinski 2023, arXiv:2306.08585, active volume и базовая архитектура), — **а не раскладка и не
компилятор**. Каждая модель предполагает структуру своей статьи (например, `gidney2025`: мало горячих кубитов,
остальные в холодном хранении), поэтому сравнивать числа можно только внутри одной модели. `qoptct estimate --check`
воспроизводит опубликованные числа (0–4 % для точной раскладки GE, Gidney 2025 и Litinski; общая модель GE
отличается сильнее, см. docstring модуля).

```
qoptct estimate --toffoli 6.5e9 --qubits 1399 --shots 9.2 --model gidney2025   # ≈ 0,89 млн физ. кубитов, ≈ 5 суток
qoptct estimate --check
```

### Точное сложение точки, остатки, модульные сумматоры, бинарные кривые (новое в 0.6)

Новые блоки в `qoptct.crypto`; используются как модули (`from qoptct.crypto import ecpoint, residue, modadd, gf2ec`).
Все числа — логические И (= Тоффоли) в той же модели, что выше.

* `ecpoint.ec_point_add(p, a, b, Q)`, `ec_point_add_window(...)`: **точное** полное прибавление известной точки Q к
  квантовой точке P на кривой над простым полем (в том числе при P = O, P = Q, P = −Q, P = −2Q); оконный вариант берёт
  Q из таблицы. P-256 / secp256k1, n = 256: 3 041 421 / 3 033 954 И (6 742 / 6 934 кубита). Это точная схема, не
  самая дешёвая из известных: приближённые схемы 2026 года (arXiv:2609.05625, arXiv:2606.02235) дешевле и с меньшим числом кубитов (у них
  ненулевая вероятность ошибки). Проверено перебором на малых кривых, на краевых точках при n = 256, фазы — разреженной
  симуляцией; машинного доказательства всей схемы нет.
* `residue.fold_accumulator(q, clen, nbits)`: сжатие аккумулятора по модулю q (loop 2 из Gidney 2025): 106 / 138 / 148 И
  при q = 1 574 500 против 682 по формуле статьи. По точному счёту схемы статьи (352–418) выигрыш меньше; стык со
  следующим шагом (loop 3) обоснован словами и на целой схеме не проверен. `qoptct kprove`: PROVED для 29 бит / окно 4
  и 32 бита / окно 4 при l = 21.
* `lookup.davio_lookup(..., fanout='gray')`: необязательный веер CX по коду Грея; до −68 % CX на больших таблицах
  (c = 10, w = 1024: 167 231 вместо 528 201 CX, те же И). Это опция, по умолчанию ничего не меняется.
* `modadd`: модульные сумматоры и вычитатели, удвоение, сравнения. Модульное сложение 4n−2 И (в публикациях 4n), выигрыш 2 И.
* `gf2ec.gf2_point_add(m, ...)`: сложение точки на бинарной кривой над GF(2^m), вторая точка известна заранее:
  m = 163: 18 160 И (10 регистров) / 29 056 (4 регистра); m = 409: 55 006. Исключительные случаи (бесконечная точка,
  P1 = P2, P1 = −P2, P1 + P2 = ±P2) **не обрабатываются**, как у Banegas и др. 2021 и Taguchi–Takayasu 2023. По
  умолчанию (`lowering='crt'`) вариант с 4 регистрами для m = 163 требует 1 142 кубита; 981 кубит — только при
  `lowering='parity'` (примерно в 6 раз больше CX).

### Модели целых атак: `qoptct estimate --attack` (новое в 0.6)

`qoptct.estimate.logical` воспроизводит логическую стоимость (И, логические кубиты) опубликованных алгоритмов для RSA,
дискретного логарифма на кривых и перебора AES методом Гровера и считает те же схемы с блоками `qoptct.crypto`. Это
инструмент оценки: **числа — модели из проверенных блоков, а не сквозные схемы.** У каждой строки есть статус:
`published` (воспроизводит число статьи), `qoptct` (блоки проверены, целая схема не собрана), `estimate` (оценка).

```
qoptct estimate --list-attacks
qoptct estimate --attack ecdlp-p256 --variant L0
qoptct estimate --attack rsa2048-g25
qoptct estimate --check-attacks        # сверка с опубликованными таблицами
```

## Честные оговорки

* Если инструменту дать список вентилей «как есть», ни один из 9 не заменяет Тоффоли на логическое И со снятием
  измерением автоматически. Если же человек сам перепишет схему как многоконтрольный Тоффоли (tof_n, barenco_tof_n),
  инструменты достигают наших чисел или лучше (PennyLane, Qiskit с конструкциями Хаттара–Гидни). Наше преимущество —
  автоматический поиск в произвольных сетях, а не лучшие гаджеты.
* Доказано не всё: если точный прувер даёт UNKNOWN (глубокая классическая логика вроде hwb, очень широкие схемы),
  схема с измерениями принимается по выборочным проверкам (много случайных входов и исходов); это видно в отчёте
  (`final.check`, `final.proof`). Требовать доказательство: `--require-proof` или `qoptct prove`.
* Выше 22 кубитов всего в режимах с измерениями работают только модули (arith, bandc, gf2m, cxpass); старые стадии
  (гаджеты H, компиляторы И версии 0.3) требуют симулятора и там пропускаются.
* Часть чисел получена более долгими поисками при разработке, чем один запуск по умолчанию (столбец «source»).
* hwb6 не включён: его файл запрещает распространение.
* Найденные ошибки (наша неверная схема hwb6 51 T, ошибка в Qrisp, ловушки tket/Qualtran) — `docs/FINDINGS.md`.
